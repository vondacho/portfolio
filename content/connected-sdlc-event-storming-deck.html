The discipline

The Event Storming decision

Human question

What happens in this domain, why does it happen, and where does responsibility belong?

Digital answer

Typed events, commands, actors, policies, systems, hotspots, and stable references.

The practice develops shared understanding through events and the decisions around them. As-Code records that understanding as a reviewable domain hypothesis rather than a workshop photograph.

Progressive precision

Three Event Storming levels

Big Picture

Landscape, language, hotspots, pivotal events.

Process Modelling

Outcomes, decisions, exceptions, external dependencies.

System Design

Software responsibility, domain rules, interfaces.

Big Picture creates shared awareness. Process Modelling narrows the focus to one outcome. System Design, called Software Design in the official pattern language, adds engineering precision. Stable identities preserve continuity across all three.

Sources: EventStorming patterns and Event Storming as Code.

The practice moves from landscape to process to system without losing language or events.

Git and GitOps

Git as source of truth and domain-model reconciliation

Git sourceAccepted model and full history
Review and mergeDomain and delivery owners approve intent
AutomationValidate, generate, publish
ReconciliationDetect drift and propose change

The visual board remains the collaborative interface. Git holds the reviewed Event Storming model and identifies the accepted revision for downstream use. GitOps-style automation pulls that revision, regenerates permitted projections, and detects stale Story Map, ticket, example, or architecture references.

Discovery still needs human judgment. The loop may update a generated view automatically, but a change to domain meaning returns to the responsible people for review.

Source: OpenGitOps principles.

Git records accepted domain intent. Automation publishes it and surfaces drift without rewriting domain meaning.

Change management

A four-step adoption path

01Pilot

Choose one value stream where workshop output currently decays.

02Connect

Generate one needed downstream artifact.

03Enforce

Add a few high-value semantic checks.

04Scale

Expand only after teams trust the workflow.

Start where translation loss hurts. Deliver one immediate benefit, such as Story Map seeds or ticket context. Add enforcement after ownership and vocabulary become clear. Scale through reusable schemas and coaching.

Sources: EventStorming patterns and Event Storming as Code.

Prove value in one flow, then add connections and enforcement.
